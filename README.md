# 双时间会员资格历史服务（连锁药房）

面向会员分析团队：在**任意历史时点**解释会员为何获得/失去等级资格，并为营销、门店预算、模型训练分别提供「当时可见」「事后补全」及「二者差异」三种口径的数据集；同时维护**会员门店归属历史与权益成本归因**，把等级、积分、生日券等权益成本按服务证据与组织沿革归到正确的药房、区域与预算周期。

技术栈：Vue 3 + FastAPI + PostgreSQL。

## 架构选型

题目要求在两种可复演历史方案中二选一，本实现选择 **追加式双时间事件账 + 可重建投影**：

- `events` 接入账是唯一事实来源：追加-only（DB 触发器禁止 UPDATE/DELETE），每行保存
  **来源哈希**（payload 的 sha256）、**链式哈希**（前序行哈希链，防篡改）、**两类时间**
  （`biz_time` 业务发生时间 / `ingested_at` 平台接收时间）、**修订链**（`supersedes_id`）、
  **幂等键**（唯一约束，重放不重复入账）。
- 身份关系图、规则版本、会员名录均为**可重建投影**：由事件重放生成，
  `POST /api/admin/rebuild` 可随时全量重建并验证结论一致。
- 取舍：更正因果直接可审计（每次变化都是一条带双时间戳的事件），代价是长窗口查询需按
  双时间过滤重放——本服务以「按 (业务时点, 系统时点) 过滤后即时重放」实现任意时点资格计算，
  并通过发布库把常用口径物化冻结，避免重复回放。

## 核心组件

| 组件 | 实现 |
| --- | --- |
| 接入账 | `events` 表：追加-only、来源哈希、链式哈希、双时间、修订链、幂等键 |
| 身份关系图 | `identity_edges` 投影：合并/拆分/待核/撤销的双时间有效区间；误合并拆分支持追溯（`retroactive`） |
| 时间语义目录 | `semantics` 表：`AS_OF`（当时可见）/ `AS_KNOWN_NOW`（事后补全）/ `DELTA`（二者差异） |
| 资格计算器 | 按业务时点、系统时点、规则版本、身份簇即时重放计算等级，输出逐范围解释 |
| 发布库 | `publications`：冻结证据水位（最大事件 id）、身份图版本、规则集版本，并物化各会员资格 |
| 差异归因器 | 比较两个发布，把每个会员的变化归因到水位之间的具体事件（迟到交易/更正/身份变更/规则修订/撤回） |
| 影响索引器 | 把等级变化映射到营销名单、门店预算、训练样本，可按下游实体反查 |

规则解析语义（确定性）：对门店 s、业务时点 T_b、系统时点 T_s，取「入账 ≤ T_s、生效区间覆盖
T_b、门店在范围内、未被覆盖 (版本, s, T_b) 的撤回命中」的版本中 (生效起点, 版本号) 最大者。
并发修订（如 v2、v3 相隔 5 分钟先后修订 v1）由该全序确定性解决，修订链完整保留在账本中。

## 会员门店归属与权益成本归因

要回答「等级会员的权益成本应归入哪家药房」，不能把成本归给最近交易门店（长期咨询/处方会被
忽略），也不能按当前门店树回填（已结算的区域预算会失真）。本域沿用同一架构：**服务关系与组织
变更同样作为事件入账，归属结果全部为可重建投影**，并冻结在结算数据集中。

| 组件 | 实现 |
| --- | --- |
| 服务关系账 | `service_relations` 投影：会员选择/处方服务/到店消费/线上履约/门店确认五类证据，保存发生时间（biz_time）、到达时间（ingested_at）、证据等级(1..5) 与撤销记录（只置 revoked，不删行） |
| 组织沿革图 | `org_intervals` 投影：门店开闭、加盟归属、区域调整、合并拆分的双时间有效区间；并购在被合并门店区间写入继承指针 |
| 归属计算器 | 指定时点为会员等级/积分/生日券计算服务门店或服务份额，输出证据、覆盖率与逐店依据 |
| 成本归因器 | `attribution_runs/lines`：把权益成本关联到门店、区域、规则版本与预算周期，冻结策略与组织/规则/证据三类版本号 |
| 结算差异发布器 | `settlement_adjustments`：定位组织修订或迟到服务证据影响的已锁定预算，保留原结算并签发调整版本 |

**两条归属路线**（预算口径 + 证据覆盖率 + 结算精度共同决定，选择结果冻结在结算单）：

- **单店归属 single_store**：每个预算期选证据等级最高的一家服务门店，成本守恒、结算直观；
  同等级非红线并列按最早业务时间确定性打破。预算不允许分摊、或覆盖率低于门槛时自动回退此路线。
- **权重分摊 apportion**：按五类证据的可解释基权（会员选择 0.20 / 处方咨询 0.30 /
  到店消费 0.30 / 线上履约 0.15 / 门店确认 0.05）分摊到多家门店；同家族多店证据按可信等级
  分配该家族基权；缺失家族的基权进入**未分配范围**，绝不平均摊给现有门店；量化产生的小数
  残差单独成 `residual` 行，归入份额最大门店且不改变份额。

**四条强制红线**（均有验收断言）：

1. 门店并购在预算期中生效 → 按每条证据的**服务发生日**解析组织节点（并购前留原店、并购后
   继承存续店），禁止月末组织树回填；
2. 会员选择门店与履约/消费证据**同可信等级且指向不同门店** → 标记 `pending_adjudication`
   待裁定，成本整额挂起，不任选门店；
3. 迟到处方服务影响**已锁定**预算 → 原结算行不变（头标记 superseded），差异发布器生成调整
   版本，按门店/未分配桶给出差额（总成本守恒，总差额为 0）；
4. 分摊缺少某类服务证据 → 按缺失基权报告 `unallocated` 未分配范围，缺口不摊给现有门店。

任一门店成本均可通过 `GET /api/attribution/lines/{id}/trace` 回查：服务关系证据、冻结的组织
沿革区间、归属策略、组织/规则/证据三个版本号、预算周期与权益成本规则版本。

## 演示场景（种子数据）

同一会员 A（13800000001）贯穿四类历史变更，另有多名对照会员：

1. **加盟店离线补传**：交易 T4 业务时间 2026-01-28，2026-03-15 才到达平台；
2. **误合并后拆分**：2026-02-15 人工裁定把 B 并入 A，2026-04-05 追溯拆分并撤销裁定；
3. **部分追溯规则撤回**：规则 v2（2026-02-01 起追溯生效，GOLD 阈值 1000→1500）于
   2026-04-10 仅对门店 S002 撤回；
4. **并发修订**：v2、v3 相隔 5 分钟先后修订 v1（另有交易 T3 的更正链 300→380）。

### 门店归属演示场景（5 名新会员，门店 S101–S105 / ONLINE，预算期 2026-02 与 2026-03）

1. **跨店服务 + 分摊残差**：会员 M1 五类证据齐全（S101 选择/处方/确认、S102 到店、ONLINE 履约），
   自动走权重分摊 0.55/0.30/0.15；其等级权益 88.88 元按 2 位精度量化产生 0.01 残差，单独成行归入 S101；
2. **证据冲突待裁定**：M2 的会员选择（S101）与线上履约（S102）同为等级 4 → 待裁定，60 元成本整额挂起；
3. **期中并购按日拆分**：S103 于 3-15 并入 S104，M3 在 3-05（留 S103）与 3-20（继承 S104）的服务
   按发生日分别解析，3 月预算（不允许分摊）整额归 S104；
4. **缺证据未分配范围**：M4 仅到店+线上两类证据（覆盖率 0.45），200 元中 110 元（缺口 0.55）报告
   未分配，不摊给 S102/ONLINE；
5. **迟到服务冲击已锁定预算**：2 月预算锁定后，M5 的 2-21 处方服务 4-12 才补传到平台，叠加 S104
   追溯区域修订（4-25 到达），差异发布器保留原结算并签发调整版本，15 元从未分配桶移入 S102，总差额为 0。

| A @ 2026-02-28 | GOLD（¥1800，簇 {A,B}） | **SILVER**（v2 范围 ¥1280 + S002 撤回后 v1 范围 ¥350） |

## 设计红线

- **不得以当前余额或当前主档覆盖历史**：系统不保存"当前等级/当前余额"字段；任何时点的
  资格都由事件账按双时间口径重放得出。误合并拆分、规则撤回等更正只追加新事件并闭合
  旧区间，历史行永不修改、永不删除。
- **门店成本不得按月末组织树回填**：每条服务证据按自身服务发生日解析组织节点，并购在
  预算期中生效时按日拆分归属；归属策略、组织沿革图版本、规则集版本、证据水位冻结在
  结算单中，可从任一归属行完整回查。
- **已锁定预算不可改写**：迟到证据或组织修订只能触发调整版本，原结算保留；待裁定成本
  不任选门店，缺证据缺口不平均摊派，分摊残差单独标注——保证全部权益成本守恒可审计。
